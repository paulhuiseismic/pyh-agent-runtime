# Feature Specification: CLI 入口（复用平台服务层）

**Feature Branch**: `008-cli-entrypoint`

**Created**: 2026-08-06

**Status**: Draft

**Input**: User description: "008 CLI 入口（复用平台服务层 AgentService，作为薄适配器，与 007 的 REST 入口共享同一套调用/调度/多租户逻辑）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过命令行发起一次 agent 调用并获得结果 (Priority: P1)

作为该 runtime 的本地使用者（开发者/运维），我在终端里执行一条命令，传入
我所属的租户身份与要完成的目标/问题，就能在同一次命令执行中获得最终结果，
无需启动或依赖一个常驻的 REST 服务进程。

**Why this priority**: 这是本 feature 的核心价值——让已经在 007 中建立的
平台处理路径（租户识别、调度、内核调用）第一次可以脱离网络服务的形式，
以本地命令行方式直接使用，是 007 architectural 承诺（"CLI 可直接复用平台
服务层而不重复实现"）的落地验证。

**Independent Test**: 可通过配置一个可用租户，在终端执行一条携带合法
API Key（环境变量）与具体问题的命令，独立验证：命令进程内正确完成租户
识别、内核调用，并在标准输出中打印最终结果文本，进程以成功退出码结束。

**Acceptance Scenarios**:

1. **Given** 已通过环境变量提供合法的租户 API Key 且已提供有效的平台配置，
   **When** 执行 CLI 命令并传入一个具体问题，**Then** 标准输出打印该问题
   对应的最终结果文本，进程以成功退出码结束。
2. **Given** 一次命令执行触发的内核处理过程中任一环节（如 LLM 调用）失败，
   **Then** 标准错误输出中包含明确可读的失败原因，进程以与"成功"不同的
   失败退出码结束，而不是无输出挂起或输出不可分类的堆栈信息。
3. **Given** 一个此前已经使用过的会话标识，**When** 再次执行 CLI 命令并传入
   同一会话标识与新问题，**Then** 该次调用复用此前该会话已经积累的上下文
   （会话记忆，003），即使这两次命令执行是完全独立的两个进程。

---

### User Story 2 - 未正确配置租户身份或平台配置时给出清晰反馈 (Priority: P2)

作为 CLI 使用者，当我忘记设置租户 API Key、设置了一个无效的 API Key，或者
平台配置本身缺失/无效（如模型服务连接信息未配置）时，我需要在命令执行的
第一时间得到清晰、可操作的错误提示，而不是含糊的报错或该命令长时间无响应。

**Why this priority**: 这是 CLI 作为"新手也可能直接上手"的入口所必须具备的
基本可用性保障，但依赖 P1 已经建立的调用路径才能验证这些前置校验时机，
因此排在其后。

**Independent Test**: 可通过分别省略环境变量中的 API Key、提供一个不存在
的 API Key、以及指向一份无效的平台配置文件这三种情形，独立验证：三种情形
下命令都在触发任何内核调用之前即失败退出，且失败原因彼此可区分。

**Acceptance Scenarios**:

1. **Given** 执行命令时未设置租户 API Key 环境变量，**When** 执行 CLI 命令，
   **Then** 命令在触发任何内核调用之前即失败退出，标准错误输出提示"未提供
   API Key"。
2. **Given** 环境变量提供的 API Key 不属于任何已配置租户，**When** 执行 CLI
   命令，**Then** 命令在触发任何内核调用之前即失败退出，标准错误输出提示
   "身份识别失败"，与"未提供 API Key"的提示可区分。
3. **Given** 指定的平台配置文件缺失或内容无效（如引用的模型未配置成本
   单价），**When** 执行 CLI 命令，**Then** 命令立即失败退出，标准错误输出
   中包含具体的配置问题描述。

---

### User Story 3 - 命令执行结果的可观测性与租户标识贯穿 (Priority: P3)

作为该平台的运维/合规方，我需要通过 CLI 发起的调用与通过 REST 入口发起的
调用一样，产生携带一致租户标识的可观测记录（span），以便按租户核算成本、
排查问题，不因为入口形式不同而在可观测性上出现盲区。

**Why this priority**: 这是 007 已确立的合规基线（内核调用必须携带
`tenant_id`）向新入口的延伸验证，技术上复用 007 已有的机制，只需确认
CLI 路径未绕过它，因此排在最后作为收尾能力。

**Independent Test**: 可通过执行一次成功的 CLI 命令后，检查该次调用触发的
全部内核可观测记录，独立验证每条记录都携带与本次调用一致的租户标识。

**Acceptance Scenarios**:

1. **Given** 一次通过 CLI 发起的成功调用，**When** 该调用触发内核的 LLM
   调用、工具调用等操作，**Then** 这些操作产生的全部可观测记录都携带与
   本次调用一致的租户标识。

---

### Edge Cases

- 平台配置文件路径未指定或指向不存在的文件时，命令 MUST 在启动阶段即
  失败退出，提示配置文件缺失，而不是使用某种隐式默认配置静默运行。
- 单次命令触发的内核处理耗时超出配置的最长等待时间时，命令 MUST 终止
  等待并以超时对应的失败退出码结束（复用 007 FR-009 的超时约束）。
- 同一租户在本机同时并发执行多条 CLI 命令（多个独立进程）时，系统
  MUST NOT 假定这些命令之间存在任何并发数量上的协调或限制——每条命令
  都是独立进程内的单次调用，本 feature 不实现跨进程/跨命令执行的并发
  协调（见 Assumptions）。
- 传入的目标/问题参数为空字符串时，命令 MUST 在触发任何内核调用之前即
  失败退出，提示"问题不能为空"。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一个命令行可执行入口，接收「目标/问题描述 +
  可选会话标识」作为调用参数，执行一次完整的 agent 调用并在同一次命令
  执行内返回最终结果，调用方无需了解内部由哪些内核能力组合完成。
- **FR-002**: 系统 MUST 通过环境变量读取调用者的租户 API Key 完成租户
  识别（复用 007 FR-011 的静态 API Key 机制）；未设置该环境变量时命令
  MUST 在触发任何内核调用之前失败退出，并提示"未提供 API Key"。
- **FR-003**: 系统 MUST 将 CLI 入口路由到与 007 REST 入口完全相同的内部
  统一处理路径（平台服务层 `AgentService`），MUST NOT 为 CLI 重新实现
  租户识别、调度、内核调用组合等已由 007 建立的逻辑。
- **FR-004**: 系统 MUST 支持调用方通过提供一个已存在的会话标识，令新的
  命令执行复用该会话此前积累的历史上下文（复用 003 的会话记忆能力，
  与 007 FR-008 语义一致）；未提供会话标识时 MUST 视为一次全新的、无
  历史上下文的调用。
- **FR-005**: 系统 MUST 在命令执行成功完成时，将最终结果文本输出到标准
  输出，并以成功退出码结束进程。
- **FR-006**: 系统 MUST 为以下情形返回彼此可区分的失败反馈（标准错误
  输出 + 相应失败退出码）：未提供 API Key、租户身份识别失败、平台配置
  缺失或无效、参数校验失败（如问题为空）、内核处理失败、请求整体处理
  超时（复用 007 FR-009 的超时约束）。CLI 单次执行为单进程单次调用
  （FR-008），不复用 007 的并发调度器（`ConcurrencyScheduler`）——
  v1 范围内没有"同一 CLI 进程内产生多个并发请求"的场景，引入调度器
  只会产生一个正常情况下必然通过、无法被真实触发的检查，属于"为未来
  假设场景预留"的过度设计（`/speckit-analyze` 发现的 F1 修正项，
  违反宪法原则 II）。
- **FR-007**: 系统 MUST 将识别出的租户标识传递给本次调用触发的每一次
  内核调用（LLM 调用、工具执行等），使这些调用产生的可观测记录都携带
  一致的租户标识（呼应宪法原则 V，与 007 FR-006 语义一致）。
- **FR-008**: 系统 MUST 采用单次执行模式——一条命令对应一次完整的 agent
  调用，命令执行完成（成功或失败）后进程即结束，MUST NOT 提供在同一
  进程内连续输入多个问题的交互式（REPL）模式（v1 范围，用户已确认）。
- **FR-009**: 系统 MUST 支持调用方指定一份平台配置文件（复用 007
  `PlatformConfig` 的配置结构：租户列表、模型服务连接信息、成本单价、
  可选 MCP server 列表等），配置缺失或无效时 MUST 在命令执行的启动阶段
  即失败退出（复用 007 FR-013/FR-014 的启动期校验语义）。
- **FR-010**: 系统 MUST 默认以纯文本形式输出结果与错误信息，MUST NOT
  在 v1 范围内提供结构化（如 JSON）输出选项（用户已确认，保持最简单
  实现）。

### Key Entities *(include if feature involves data)*

- **CLI 调用参数**：一次命令执行的输入，包含目标/问题描述、可选的会话
  标识、平台配置文件路径；租户身份通过环境变量单独提供，不作为命令行
  参数出现。
- **CLI 调用结果**：一次命令执行完成后的输出，包含标准输出的成功结果
  文本，或标准错误输出的失败原因描述与对应的进程退出码。
- **租户 API Key（环境变量）**：调用者所属租户的凭据，来源与 007 REST
  入口的 API Key 相同的租户配置表，只是传递方式从 HTTP 请求头变为进程
  环境变量。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者无需启动或运行任何常驻网络服务，即可通过一条本地
  命令获得一次 agent 调用的最终结果。
- **SC-002**: 100% 未提供合法租户 API Key 的命令执行，在触及任何内核
  资源（LLM 调用、工具执行等）之前即失败退出。
- **SC-003**: CLI 入口的租户识别、内核调用组合逻辑与 007 REST 入口共享
  同一套实现——衡量方式为：新增 CLI 入口未修改或复制 007 已有的
  `AgentService`/租户识别相关实现代码。
- **SC-004**: 每一次通过 CLI 发起的成功调用触发的内核可观测记录，100%
  携带与该次调用一致的租户标识。
- **SC-005**: 同一会话标识下，跨多次独立命令执行的调用，100% 能够看到
  此前调用积累的会话上下文，与调用是否来自 REST 入口无关。
- **SC-006**: 全部可区分的失败情形（缺少 API Key、身份识别失败、配置
  无效、参数校验失败、内核失败、超时）在使用者查看标准错误输出与退出码
  时，100% 可以彼此区分，无需查看内部日志。

## Assumptions

- CLI 采用单次执行模式（FR-008）：一条命令 = 一次调用，不提供进程内
  连续多轮对话的交互式（REPL）体验；跨多次调用的会话延续通过显式传入
  同一会话标识实现，而非保持进程常驻。
- 租户身份通过环境变量传递 API Key（FR-002），不通过命令行参数传入，
  以避免明文租户凭据出现在 shell 历史记录或进程列表中；具体环境变量名
  在 plan/contracts 阶段确定。
- CLI 每次执行都是独立的操作系统进程，不共享任何跨进程状态；本 feature
  不复用 007 的 `ConcurrencyScheduler`（并发调度器）——单进程单次调用
  没有真实存在的"并发上限"场景需要保护，引入该组件只会产生一个正常
  情况下必然通过、无法被真实触发的检查（`/speckit-analyze` F1 修正项，
  避免违反宪法原则 II 的"不为未来假设场景预留扩展点"）；跨进程/跨命令
  执行的并发协调本 feature 不实现，留给未来按需评估。
- 输出格式为纯文本（FR-010），不在 v1 提供结构化（JSON）输出选项；
  未来如需被其他脚本消费，可作为独立增量按需添加。
- 本 feature 复用 007 建立的 `AgentService`/`PlatformConfig`/租户识别
  等实现，不重新设计这些组件的行为；CLI 只负责将命令行输入适配为对
  这些既有组件的调用，以及将调用结果适配为终端可读的输出。
- 平台配置文件的结构与来源与 007 `PlatformConfig` 一致（可复用同一份
  配置文件），但 CLI 场景下不需要 007 中"网络服务监听端口"等仅与 REST
  入口相关的配置项。
